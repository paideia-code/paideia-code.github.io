# Cómo crear contenido

## Elegir `.md` o `.mdx`

- Usa **`.md`** para texto, listas, tablas, imágenes y enlaces sin componentes interactivos.
- Usa **`.mdx`** cuando necesites componentes React globales, expresiones JSX o contenido enriquecido.

## Front matter básico

El front matter va al principio del archivo entre dos líneas de `---`:

```md
---
title: Introducción a las colas
sidebar_position: 1
---
```

`title` define el título visible y `sidebar_position` ordena el documento cuando el sidebar es automático. El slug puede personalizarse si hace falta, pero conviene dejar que Docusaurus lo derive de la ruta.

## Añadir un documento a una sección

Guarda el archivo dentro de la carpeta de la sección adecuada, por ejemplo `docs/theory/fundamentals/algoritmos/colas.md` o `docs/projects/paideia-code-site/nuevo-tema.mdx`. La carpeta determina la familia de rutas y el sidebar asociado. Mantén nombres de archivo descriptivos y una única responsabilidad por documento.

Los sidebars de este portal usan categorías y, para Projects, un sidebar automático (`autogenerated`). Por ello, un nuevo archivo dentro de `docs/projects/paideia-code-site/` aparece automáticamente en la navegación; su `sidebar_position` controla el orden.

## Enlaces internos

Usa rutas relativas entre documentos de la misma sección:

```md
Consulta [la estructura del portal](estructura).
```

También puedes enlazar una ruta explícita como `[componentes](/projects/paideia-code-site/componentes)`, aunque las rutas relativas suelen ser más portables entre desarrollo y despliegue.

## Componentes globales

Como están registrados en `src/theme/MDXComponents.tsx`, puedes usar los componentes sin imports:

```mdx
<ConceptCard title="Idea clave">
  El contenido MDX puede combinar texto con componentes React.
</ConceptCard>

<Quiz
  question="¿Qué archivo controla la configuración general?"
  options={[
    {text: 'docusaurus.config.ts', correct: true},
    {text: 'build/index.html'},
  ]}
/>

<DrawioIframe src="https://viewer.diagrams.net/?url=URL_CODIFICADA" />
```

## Reglas para evitar errores MDX

- Escribe los nombres de componentes con mayúscula inicial: `ConceptCard`, no `conceptCard`.
- Escapa `<` y `{` cuando formen parte de texto literal, o usa un bloque de código.
- Usa bloques de código delimitados por tres backticks para ejemplos de sintaxis.
- Cierra siempre las etiquetas JSX y las llaves de arrays/props.
- Comprueba que las props tengan el tipo esperado y que las URLs sean válidas.

## Checklist

Antes de terminar un documento:

- [ ] Tiene front matter con título y posición adecuados.
- [ ] Está en la carpeta de la sección correcta.
- [ ] Sus enlaces internos funcionan con el `baseUrl` del portal.
- [ ] Los componentes globales no tienen imports innecesarios.
- [ ] El documento se lee correctamente en `npm run start`.
- [ ] `npm run typecheck` y `npm run build` terminan sin errores.
