# Regiones, Availability Zones y arquitectura global


> **🧭 En una mirada**
> - **Qué es:** la organización geográfica y aislada de la infraestructura de AWS.
> - **Por qué importa:** afecta latencia, residencia de datos, disponibilidad y precio.
> - **Cómo funciona:** una región contiene varias Availability Zones conectadas con baja latencia.
> - **Para qué se usa:** escoger ubicación y distribuir componentes para tolerar fallos.

## Jerarquía

```text
AWS Global Infrastructure
  └── Región
        └── Availability Zone
              └── uno o más datacenters
```

- **Región**: área geográfica aislada.
- **Availability Zone (AZ)**: ubicación aislada dentro de una región.
- **Edge location**: punto de presencia usado por servicios como CloudFront.

## Cómo elegir una región

Considera:

- Latencia para los usuarios.
- Disponibilidad del servicio y sus funcionalidades.
- Precio.
- Requisitos legales y residencia de datos.
- Proximidad a otras dependencias.

## Patrones

### Una AZ

Útil para laboratorios, barata y simple. No ofrece tolerancia a la caída de esa AZ.

### Varias AZ

Patrón habitual para producción: balanceador y cómputo distribuidos, base de datos con configuración Multi-AZ y subredes privadas por AZ.

### Varias regiones

Solo cuando la continuidad de negocio, latencia o requisitos legales lo justifican. Incrementa mucho la complejidad de datos, despliegues y costes.

## Responsabilidad del desarrollador

Conocer dónde se crean los recursos, qué datos contienen y qué sucede si la región o una AZ no está disponible.
