# Modelo de responsabilidad compartida


> **🧭 En una mirada**
> - **Qué es:** el reparto de responsabilidades de seguridad entre AWS y el cliente.
> - **Por qué importa:** usar un servicio gestionado no elimina la responsabilidad sobre datos y configuración.
> - **Cómo funciona:** AWS protege la infraestructura; el alcance del cliente cambia según el servicio.
> - **Para qué se usa:** asignar controles, pruebas y tareas operativas correctamente.

AWS protege **la seguridad de la nube**: instalaciones, hardware, red física y capa de virtualización.

El cliente protege **la seguridad en la nube**: identidades, datos, configuración, sistema operativo cuando aplica, red lógica y aplicación.

## Según el servicio

| Servicio | Cliente sigue siendo responsable de |
|---|---|
| EC2 | Sistema operativo, parches, aplicación y Security Groups |
| RDS | Datos, usuarios de BD, configuración lógica y acceso |
| S3 | Policies, bucket configuration, objetos y cifrado elegido |
| Lambda | Código, dependencias, permisos y datos |
| ECS Fargate | Imagen, configuración, roles y aplicación |

## Preguntas de revisión

- ¿Quién aplica los parches?
- ¿Quién configura la autenticación?
- ¿Quién cifra los datos?
- ¿Quién conserva y revisa los logs?
- ¿Quién configura la red?

La respuesta cambia según el servicio, pero AWS nunca elimina la responsabilidad sobre los datos y las identidades.
