# Routing, conectividad y seguridad de red


> **🧭 En una mirada**
> - **Qué es:** el enrutamiento y los controles que permiten o bloquean tráfico.
> - **Por qué importa:** muchos fallos de despliegue son rutas, DNS o reglas mal alineadas.
> - **Cómo funciona:** route tables, security groups, NACLs, NAT y endpoints determinan el flujo.
> - **Para qué se usa:** conectar capas con el mínimo acceso necesario y diagnosticar conectividad.

## Security Groups

Son stateful: si se permite una conexión de entrada, la respuesta queda permitida automáticamente. Solo contienen reglas allow.

Ejemplo para una API:

```text
ALB SG       → permite 443 desde Internet
App SG       → permite 8080 únicamente desde ALB SG
Database SG  → permite 5432 únicamente desde App SG
```

Referenciar Security Groups es preferible a permitir rangos IP amplios.

## Network ACLs

Son stateless, aplican a nivel de subnet y requieren permitir explícitamente ida y vuelta. Son útiles como defensa adicional, pero no deben sustituir el diseño de Security Groups.

## Conectividad privada

- VPC Peering conecta VPCs de forma directa.
- Transit Gateway centraliza conectividad entre muchas VPCs.
- VPC Endpoints permiten llegar a servicios AWS sin salir a Internet; pueden reducir exposición y costes.
- VPN y Direct Connect conectan redes corporativas con AWS.

## Diagnóstico

Cuando un servicio no conecta, revisar en orden:

1. DNS y nombre resuelto.
2. Ruta de la subnet.
3. Internet Gateway o NAT.
4. Security Groups de origen y destino.
5. Network ACL.
6. Puerto de escucha de la aplicación.
7. Logs y VPC Flow Logs.
