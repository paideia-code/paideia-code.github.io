# VPC y subredes


> **🧭 En una mirada**
> - **Qué es:** una red virtual aislada con rangos IP y subredes en AWS.
> - **Por qué importa:** la topología determina exposición, conectividad, latencia y disponibilidad.
> - **Cómo funciona:** subredes, tablas de rutas, gateways y controles de tráfico forman el camino.
> - **Para qué se usa:** separar capas públicas y privadas y conectar aplicaciones con dependencias.

## Componentes

- **VPC**: red lógica aislada con un CIDR.
- **Subnet**: segmento de IP dentro de una AZ.
- **Route table**: reglas para decidir el siguiente salto.
- **Internet Gateway**: conectividad con Internet para recursos públicos.
- **NAT Gateway**: salida a Internet desde subredes privadas; no acepta conexiones entrantes iniciadas desde Internet.
- **Security Group**: firewall stateful asociado a interfaces.
- **Network ACL**: filtro stateless asociado a subredes.

## 🧩 Decisión: público o privado

| Recurso | Subnet habitual | Motivo |
|---|---|---|
| Application Load Balancer | Pública | Recibe tráfico de Internet |
| ECS/EC2 de aplicación | Privada | No necesita exposición directa |
| RDS | Privada | Debe aceptar tráfico solo de la aplicación |
| NAT Gateway | Pública | Permite salida controlada desde subnets privadas |

> **⚠️ Atención:** una subnet “pública” no vuelve automáticamente público a todo recurso. Deben coincidir la tabla de rutas, la dirección IP y las reglas de seguridad.

## Diseño mínimo

```text
VPC
├── public-subnet-a  → ALB / NAT
├── public-subnet-b  → ALB / NAT
├── private-app-a    → ECS / EC2
├── private-app-b    → ECS / EC2
└── private-data-a/b → RDS
```

La ruta por sí sola no hace pública una subnet: también se necesita una ruta al Internet Gateway y recursos con dirección pública cuando corresponda.

## Reglas prácticas

- Elegir un CIDR que no colisione con redes futuras.
- Distribuir producción en al menos dos AZ.
- Colocar bases de datos en subredes privadas.
- No abrir `0.0.0.0/0` a puertos administrativos salvo laboratorio controlado.
- Documentar qué flujo debe existir antes de abrir un puerto.

## ⚠️ Errores frecuentes

- Poner la base de datos en una subnet pública.
- Confundir `0.0.0.0/0` en una ruta con permiso de entrada.
- Abrir la aplicación directamente a Internet en lugar de usar un ALB.
- Olvidar que NAT Gateway tiene coste aunque el tráfico sea pequeño.

## ✅ Comprobación

Para cada flujo dibuja: origen → DNS → subnet → route table → gateway → Security Group → destino. Si no puedes seguir el camino completo, todavía falta información de la red.
