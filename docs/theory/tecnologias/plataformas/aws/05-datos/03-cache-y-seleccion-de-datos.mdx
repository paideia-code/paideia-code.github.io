# Caché y selección de datos


> **🧭 En una mirada**
> - **Qué es:** criterios para usar caché y seleccionar almacenes según el problema.
> - **Por qué importa:** una caché mejora latencia, pero añade invalidación, consistencia y coste.
> - **Cómo funciona:** se separan datos fuente, datos derivados y consultas calientes.
> - **Para qué se usa:** reducir carga, acelerar lecturas y escoger entre RDS, DynamoDB, Redis o almacenes analíticos.

## ElastiCache

Servicio gestionado para Redis o Valkey. Puede almacenar resultados, sesiones, locks y contadores, pero no debe convertirse accidentalmente en la única copia de datos importantes.

## Estrategias de caché

- Cache-aside: la aplicación consulta caché y carga desde la base si no encuentra el dato.
- TTL: evita datos eternamente obsoletos.
- Invalidación explícita: necesaria tras cambios críticos.
- Protección contra cache stampede: backoff, locks o precarga.

## Elección rápida

| Necesidad | Primera opción a evaluar |
|---|---|
| Datos relacionales y consultas complejas | RDS/Aurora |
| Objetos y archivos | S3 |
| Acceso clave-valor altamente escalable | DynamoDB |
| Cache y sesiones | ElastiCache |
| Analítica sobre grandes volúmenes | Redshift, Athena o servicios de analytics |
