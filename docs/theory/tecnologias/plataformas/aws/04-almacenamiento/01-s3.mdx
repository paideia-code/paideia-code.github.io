# Amazon S3


> **🧭 En una mirada**
> - **Qué es:** almacenamiento de objetos organizado en buckets y claves.
> - **Por qué importa:** ofrece durabilidad, escalado y políticas de acceso sin gestionar discos.
> - **Cómo funciona:** objetos, clases de almacenamiento, versionado, lifecycle y policies colaboran.
> - **Para qué se usa:** archivos, backups, contenido estático, eventos y datos de aplicación.

## Modelo

S3 almacena objetos dentro de buckets. Un objeto tiene clave, contenido, metadatos y opcionalmente una versión.

## Conceptos

- Buckets con nombre globalmente único.
- Versioning.
- Storage classes.
- Lifecycle rules.
- Cifrado.
- Bucket policy y Block Public Access.
- URLs prefirmadas.
- Eventos hacia Lambda, SQS o EventBridge.

## 🧩 Clases y decisión

| Necesidad | Primera opción |
|---|---|
| Acceso frecuente | S3 Standard |
| Acceso poco frecuente pero inmediato | Intelligent-Tiering o una clase IA |
| Archivo que casi nunca se consulta | Glacier según el RTO |
| Datos temporales | Lifecycle hacia una clase económica o eliminación |

La clase no sustituye una política de retención. Diseña ambas: cuándo se accede y cuándo deja de ser necesario.

## Diseño seguro

- Mantener Block Public Access salvo necesidad justificada.
- Conceder acceso mediante roles.
- Separar prefijos por responsabilidad.
- Activar versionado cuando sea importante recuperar objetos.
- Definir lifecycle para objetos temporales.
- No usar S3 como base de datos relacional.

## Integración con Paideia

`content-service` puede guardar archivos en S3 y persistir en MongoDB o una base relacional únicamente la metadata. El cliente puede recibir una URL prefirmada con duración limitada, sin hacer público el bucket.

## ⚠️ Errores frecuentes

- Hacer público el bucket para resolver un problema de permisos.
- Confundir una clave S3 (`cursos/intro/video.mp4`) con una carpeta real.
- Olvidar versionado, lifecycle o límites de tamaño en cargas grandes.
- Guardar secretos en metadata o nombres de objetos.

## ✅ Comprobación

Verifica que un rol de aplicación pueda leer el prefijo esperado, pero no listar o eliminar objetos fuera de su responsabilidad.
