# Lambda y API Gateway


> **🧭 En una mirada**
> - **Qué es:** ejecución de funciones bajo demanda y exposición gestionada de APIs.
> - **Por qué importa:** acelera entregas y escala automáticamente, con límites y modelo de invocación propios.
> - **Cómo funciona:** API Gateway recibe la petición y Lambda ejecuta código con un rol de ejecución.
> - **Para qué se usa:** APIs, automatizaciones, integraciones y procesamiento por eventos.

## Lambda

Ejecuta funciones como respuesta a invocaciones. AWS gestiona servidores y escalado; tú gestionas código, dependencias, configuración, permisos y datos.

Considera:

- Cold starts.
- Tiempo máximo y memoria.
- Concurrencia.
- Reintentos e idempotencia.
- Límites de payload.
- Logs y trazas.
- Estado fuera de la función.

## API Gateway

Expone APIs HTTP, REST o WebSocket y puede integrar Lambda, ECS y otros destinos. Proporciona routing, autenticación, throttling, stages y observabilidad.

## 🧩 Lambda frente a ECS

| Criterio | Lambda | ECS/Fargate |
|---|---|---|
| Operación | Muy gestionada | Gestionada, pero con contenedor |
| Duración | Limitada por ejecución | Adecuada para procesos largos |
| Escalado | Por invocación y concurrencia | Por tareas y métricas |
| Empaquetado | ZIP o imagen | Imagen Docker |
| Mejor ajuste | Eventos y cargas variables | APIs y workers persistentes |

## ⚠️ Errores frecuentes

- Crear funciones con estado local como si fueran servidores persistentes.
- Ignorar reintentos y procesar dos veces el mismo evento.
- Dar permisos administrativos a la execution role.
- No configurar timeouts coherentes con la dependencia externa.
- Confundir timeout de API Gateway con timeout de Lambda.

## Cuándo elegirlo

Lambda funciona bien con tráfico variable, tareas cortas y eventos. ECS es más predecible para procesos largos, APIs con tráfico constante o workloads ya empaquetados como contenedores.
