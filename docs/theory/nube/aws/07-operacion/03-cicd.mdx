# CI/CD en AWS


> **🧭 En una mirada**
> - **Qué es:** automatización de integración, pruebas, entrega y despliegue.
> - **Por qué importa:** acorta ciclos sin sacrificar controles ni trazabilidad.
> - **Cómo funciona:** cambios versionados atraviesan validaciones, artefactos, permisos y ambientes.
> - **Para qué se usa:** publicar software repetible con rollback y estrategias seguras.

## Pipeline básico

```text
Git push
  → tests y lint
  → build de imagen
  → scan
  → push a ECR
  → despliegue ECS
  → smoke tests
```

Puede implementarse con GitHub Actions, CodePipeline, CodeBuild y CodeDeploy. La herramienta es secundaria frente a comprender artefactos, entornos, rollback y permisos.

## Buenas prácticas

- Separar build y deploy.
- Usar tags de imagen inmutables o digest.
- No desplegar directamente desde el portátil.
- Aprobar producción de forma explícita.
- Tener rollback probado.
- Usar OIDC para que el proveedor CI asuma un rol temporal.
- Guardar logs de cada ejecución.
