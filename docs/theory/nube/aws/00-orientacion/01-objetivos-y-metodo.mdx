# Objetivos y método de estudio


> **🧭 En una mirada**
> - **Qué es:** el plan de aprendizaje y la forma de practicar cada tema.
> - **Por qué importa:** evita estudiar servicios aislados sin comprender decisiones ni costes.
> - **Cómo funciona:** combina teoría breve, laboratorio, fallo deliberado y reflexión.
> - **Para qué se usa:** avanzar desde fundamentos hasta diseño y entrega de aplicaciones.

## Objetivos

Al terminar la ruta deberías poder:

- Explicar los conceptos básicos de cloud y AWS.
- Crear una cuenta de laboratorio razonablemente segura.
- Desplegar una API con contenedores.
- Conectar una aplicación con S3 y RDS.
- Diseñar una VPC básica.
- Usar roles IAM en vez de secretos embebidos.
- Implementar procesamiento asíncrono con SQS y SNS.
- Observar, diagnosticar y controlar costes.
- Automatizar infraestructura con Terraform o CDK.
- Explicar las decisiones de arquitectura de una aplicación.

## Qué no se pretende inicialmente

- Memorizar todos los servicios de AWS.
- Aprender Kubernetes antes de entender redes y contenedores.
- Usar cada servicio gestionado solo porque existe.
- Crear arquitecturas multi-región desde el principio.

## Método por tema

Para cada servicio:

1. Identificar el problema que resuelve.
2. Entender su modelo de responsabilidad y facturación.
3. Leer el modelo de seguridad.
4. Ejecutar un laboratorio pequeño.
5. Repetirlo con AWS CLI o Infrastructure as Code.
6. Introducir un fallo deliberado y diagnosticarlo.
7. Compararlo con una alternativa.
8. Documentar cuándo lo usarías y cuándo no.

## Ritmo sugerido

Con 8-10 horas semanales:

| Periodo | Resultado |
|---|---|
| Semanas 1-2 | Fundamentos, cuenta, IAM y costes |
| Semanas 3-5 | VPC, EC2, S3 y CloudFront |
| Semanas 6-7 | RDS, DynamoDB y caché |
| Semanas 8-9 | Lambda, API Gateway y mensajería |
| Semanas 10-12 | ECS, observabilidad e IaC |
| Semanas 13-16 | Proyecto Paideia y preparación de examen |

## Regla de aprendizaje

Una etapa está suficientemente aprendida cuando puedes:

- Explicarla con tus propias palabras.
- Crear una versión mínima.
- Describir los fallos más comunes.
- Identificar los permisos necesarios.
- Estimar los principales costes.
- Eliminar y recrear los recursos.
