# Amazon RDS


> **🧭 En una mirada**
> - **Qué es:** servicio gestionado para motores de bases de datos relacionales.
> - **Por qué importa:** reduce tareas operativas, pero no resuelve automáticamente diseño ni consultas.
> - **Cómo funciona:** AWS gestiona parte de infraestructura; el equipo configura red, acceso y datos.
> - **Para qué se usa:** aplicaciones que necesitan SQL, transacciones y un modelo relacional conocido.

## Qué resuelve

RDS gestiona tareas operativas de motores relacionales como PostgreSQL y MySQL: provisioning, backups, parches y ciertas opciones de alta disponibilidad.

## Conceptos

- DB instance y engine.
- DB subnet group en subredes privadas.
- Security Group de base de datos.
- Backups automáticos y snapshots.
- Multi-AZ para disponibilidad.
- Read replica para escalar lecturas.
- Parameter groups y option groups.

## 🧩 Alta disponibilidad frente a escalado

| Necesidad | Mecanismo |
|---|---|
| Recuperar una instancia ante fallo de infraestructura | Multi-AZ |
| Escalar lecturas | Read replicas |
| Recuperar datos borrados | Backups y point-in-time recovery |
| Probar un cambio aislado | Snapshot y entorno separado |

Multi-AZ no es lo mismo que una read replica: el primero prioriza disponibilidad; la segunda, capacidad de lectura.

## RDS no elimina la responsabilidad de la aplicación

Tú sigues gestionando:

- Esquema y migraciones.
- Usuarios de base de datos.
- Índices y consultas.
- Pool de conexiones.
- Retención y restauración probada.
- Compatibilidad de versiones.

## Patrón para Paideia

Cada servicio puede tener su propia base lógica o instancia según el objetivo del laboratorio. La regla conceptual `database-per-service` sigue siendo importante, aunque el coste y la operación pueden justificar una instancia compartida con bases separadas durante un laboratorio.

## ⚠️ Errores frecuentes

- Exponer el puerto 5432 a Internet.
- Crear una instancia sobredimensionada para un laboratorio.
- No configurar backups ni probar una restauración.
- Abrir demasiadas conexiones desde cada task de ECS.
- Tratar Multi-AZ como sustituto de una estrategia de backup.
