# SOLID

SOLID reúne cinco heurísticas para diseñar colaboraciones orientadas a objetos:

- **S — Single Responsibility:** una unidad tiene un motivo principal de cambio.
- **O — Open/Closed:** extender comportamiento no debería exigir modificar políticas estables.
- **L — Liskov Substitution:** una implementación sustituible respeta el contrato de su abstracción.
- **I — Interface Segregation:** los clientes no dependen de operaciones que no usan.
- **D — Dependency Inversion:** las políticas dependen de contratos, no de detalles.

## Uso responsable

SOLID ayuda a formular preguntas sobre cohesión, contratos y dependencias; no obliga a crear jerarquías o interfaces. Aplica el principio que resuelva una presión observable y verifica que la abstracción reduzca el coste de cambio.
