# DDD

## Definición e intención

Domain-Driven Design (DDD) orienta el diseño alrededor del dominio, su lenguaje y sus límites, conectando modelo conceptual y decisiones de software.

## Problema

Los términos ambiguos y un modelo técnico desconectado de las reglas reales generan errores de comunicación y límites artificiales.

## Aplicación

Construye lenguaje ubicuo con expertos, identifica entidades, objetos valor, agregados, servicios y eventos, y separa [bounded contexts](./bounded-contexts) cuando los significados divergen.

## Beneficios y trade-offs

Mejora la alineación entre negocio y código y concentra invariantes. Requiere colaboración sostenida y puede ser excesivo para dominios simples; no prescribe microservicios.

## Relaciones

Se combina con monolito modular, arquitectura hexagonal, bounded contexts y vertical slicing.
